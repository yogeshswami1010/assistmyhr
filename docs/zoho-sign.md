# Zoho Sign for offer letters

1. Create a Zoho OAuth client in the same data center as your Zoho Sign organization. Generate an offline refresh token with `ZohoSign.documents.CREATE,ZohoSign.documents.READ,ZohoSign.documents.UPDATE`. Set the client ID, secret, refresh token, and regional suffix (for example, `in` for `sign.zoho.in`) in the ATS server environment. [Zoho OAuth setup](https://www.zoho.com/sign/api/oauth.html) · [Zoho data centers](https://www.zoho.com/sign/api/api-endpoint.html)
2. The ATS uses these server credentials for every workspace. Run `php artisan migrate --force`, then `php artisan saas:migrate --force` for SaaS deployments. Run `php artisan config:cache` after editing the server environment.
3. Set `ZOHO_SIGN_WEBHOOK_SECRET` and register a single callback at `https://YOUR-ATS-DOMAIN/zoho-sign-webhook` in Zoho Sign's API settings. Enable HMAC using the same secret and subscribe to **Sent**, **Completed by all**, decline, recall, and expiration. The ATS routes events by their Zoho request ID. If a callback is delayed, use **Refresh status** in **Document Sign**. [Zoho webhook security](https://help.zoho.com/portal/en/kb/zoho-sign/admin-guide/webhooks/articles/securing-zoho-sign-webhooks-with-hmac-authentication)
4. Set the applicant's status to **Hired**, open **Document Sign**, and select **Upload PDF**. Upload the PDF, then select **Open Zoho editor**. Place the signature, signing date, and any additional fields in Zoho, then click **Send**. Your Zoho Sign plan must support embedded sending. [Zoho embedded sending](https://www.zoho.com/sign/api/embedded-sending.html)
5. Zoho emails the signing link directly to the applicant. Once complete, use **Download signed PDF** in **Document Sign** to retrieve the signed document and completion certificate. Recall an active request in Zoho Sign to cancel it.

For a trial with your own test recipient, set `ZOHO_SIGN_TESTING=true`. Zoho applies a permanent test watermark to documents sent in this mode. [Zoho API testing](https://www.zoho.com/sign/api/getting-started-with-zoho-sign-api.html)

For a staging test without a refresh token, generate a temporary token in **Zoho Sign → Developer settings → API token - development** and set `ZOHO_SIGN_DEVELOPMENT_TOKEN` on the ATS server. Set `ZOHO_SIGN_TESTING=true` and run `php artisan config:cache`. The token expires after 60 minutes and is ignored when testing is off. For production, use the refresh token from **API token - deployment** and remove the development token from the server environment. [Zoho API token setup](https://www.zoho.com/sign/api/quick-start-with-zoho-sign-api.html)
